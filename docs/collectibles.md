# Digital collectibles (XRPL-070 to XRPL-075)

Artist-made NFTs sold as merchandise: artwork, a track, a clip. **A collectible is not a ticket.** It
never grants entry to an event and never appears in ticket lists, inventory or check-in.

Code: `src/features/collectibles/` (services and UI), `src/contracts/collectibles.ts` (contracts, not
re-exported from `src/contracts/index.ts`), routes under `src/app/api/assets`, `src/app/api/collectibles`
and `src/app/api/sellers/[id]/collectibles`, pages under `src/app/collectibles` and
`src/app/seller/collectibles`.

## Flow

1. **Upload (XRPL-070).** On `/seller/collectibles` a seller picks an image, audio or video file and
   ticks the rights declaration. The browser uploads it with a progress bar.
2. **Describe (XRPL-072).** Title, description, edition size (1 to 100), price per edition in XRP and
   a statement of what buyers receive. This creates a `DRAFT`. A draft and its media are visible only
   to the seller.
3. **Publish.** Makes the listing (`/collectibles/:id`), the media and the NFT metadata public, fixes
   the details the metadata is built from, and creates one `CollectibleToken` per edition, each with its
   stable metadata URI. So every edition's metadata can be fetched before it is minted.
4. **Mint (XRPL-073).** "Mint next edition" asks the seller's own Xaman wallet to sign an `NFTokenMint`.
   One approval per edition; the app never holds a key.
5. **List for sale (XRPL-074).** For a minted edition the seller signs an `NFTokenCreateOffer` (sell
   offer at the collectible's price, open to anyone).
6. **Buy (XRPL-074).** A customer with a connected wallet presses Buy on the listing and signs an
   `NFTokenAcceptOffer`. The ledger swaps the NFT and the XRP atomically.
7. **Collection (XRPL-075).** `/collectibles` shows the collectibles the signed-in wallet holds, each
   checked on a validated ledger, separately from `/tickets`.

## Data model

Migration `20261121040234_add_digital_collectibles`. Own tables on purpose: nothing here reads or
writes `TicketNFT`, `NFTOffer` or `LedgerTransaction`, so ticket queries, inventory and check-in never
see a collectible.

| Model | Holds |
|---|---|
| `MediaAsset` | Uploader, kind (`IMAGE`/`AUDIO`/`VIDEO`), MIME type, size, storage key (the media location), original file name, `rightsConfirmedAt` |
| `Collectible` | Seller, media asset, title, description, edition size, price in drops, rights statement, `DRAFT`/`PUBLISHED` |
| `CollectibleToken` | One edition: edition number, metadata URI, then three stages, each with its wallet request ID and validated transaction hash: **mint** (`mintStatus`, `nftokenId`, issuer), **sell offer** (`offerStatus`, `offerIndex`, amount), **purchase** (`saleStatus`, buyer address, `saleTxHash`); plus `ownerAddress` as last confirmed on the ledger |

`User` gains the back-relations `mediaAssets` and `collectibles`. CHECK constraints: positive media size,
positive drops price, edition size 1 to 100, edition number at least 1.

## Media storage (XRPL-071)

- Media is stored **off-chain** through the `MediaStorage` interface (`storage.ts`: `put`, `size`,
  `read` with an optional byte range, `delete`). The adapter that ships is `LocalDiskMediaStorage`.
- Directory: env `MEDIA_STORAGE_DIR`, default `./storage/media` (git-ignored, **not** under `public/`).
- Storage keys are generated by the server (`<uuid>.<ext>`); a file name from the browser is never used
  as a path. The adapter refuses any key that is not in that form.
- Supported types and limits: PNG, JPEG, WebP, GIF up to 10 MB; MP3, WAV, OGG, FLAC, M4A up to 25 MB;
  MP4, WebM up to 50 MB. The type is decided from the file's own signature, not from the browser's label
  or the file name. SVG and HTML are not accepted.
- **Access.** `GET /api/assets/:id/content` serves the bytes only when the asset belongs to a published
  collectible, or the requester is its uploader. Otherwise 404. It sends the stored type with
  `X-Content-Type-Options: nosniff`, and supports `Range` (at most 4 MB per ranged response) so audio
  and video can seek.

## Metadata and the rights statement (XRPL-072)

`GET /api/collectibles/tokens/:id/metadata` returns raw JSON (no `{ data }` envelope, CORS open), the
same before and after minting:

```json
{
  "schema": "xrpl-ticketing/collectible@1",
  "nftType": "collectible.v1",
  "name": "<title> #<i>/<N>",
  "description": "Digital collectible by <seller>: edition <i> of <N>. Not an event ticket. <description>",
  "image": "<media URL>",
  "collection": { "name": "<title>", "family": "XRPL Ticketing Collectibles" },
  "attributes": [{ "trait_type": "Creator", "value": "..." }, { "trait_type": "Edition", "value": 1 }],
  "media": { "url": "<base>/api/assets/<assetId>/content", "kind": "IMAGE", "mimeType": "image/png", "sizeBytes": 12345 },
  "creator": { "sellerId": "...", "name": "...", "profileUrl": "<base>/sellers/<sellerId>" },
  "edition": { "number": 1, "of": 10 },
  "collectible": { "collectibleId": "...", "tokenId": "...", "network": "TESTNET", "listingUrl": "<base>/collectibles/<id>" },
  "rights": { "statement": "...", "copyrightTransferred": false, "copyrightNotice": "...", "grantsEventEntry": false }
}
```

`image` becomes `audio` or `video` for those kinds. No buyer or holder is ever named.

**Rights.** Every listing shows, under "What you get when you buy":

- the seller's statement (`Collectible.rightsStatement`). Default: *"The buyer owns this numbered edition
  as an NFT and may keep, display, resell or give it away. The buyer may view or play the media for
  personal, non-commercial use."*
- a fixed notice the seller cannot remove: *"Copyright is not transferred automatically. Unless the
  creator grants more in writing, the creator keeps the copyright and every other right in the work;
  buying the NFT does not let you copy, publish or sell the content itself."*
- *"A digital collectible is not a ticket. Buying or holding one does not grant entry to any event."*

The base URL is `ticketPublicBaseUrl()` (`TICKET_METADATA_BASE_URL`, else `APP_BASE_URL`). As for
tickets, it must be the app's public https address wherever collectibles are minted for real: a URI on
the ledger cannot change.

## On the ledger (XRPL-073/074)

| | Value |
|---|---|
| `NFTokenTaxon` | `COLLECTIBLE_TAXON` = `0xC011EC71`, fixed. Tickets use a per-event taxon; identity always comes from the app's own tables, the taxon is a grouping hint |
| `Flags` | `tfTransferable` (8). Not burnable by the issuer, no transfer fee |
| `URI` | Hex of the edition's metadata URL |
| Memo | type `xrpl-ticketing/collectible`, data = the `CollectibleToken` ID (on the mint, the sell offer and the purchase) |
| Transaction purposes | `MINT_COLLECTIBLE` (NFTokenMint), `CREATE_COLLECTIBLE_OFFER` (NFTokenCreateOffer), `ACCEPT_COLLECTIBLE_OFFER` (NFTokenAcceptOffer) |

Rules (`ledger.ts`):

- The server builds every transaction. The signer is the session's proven wallet
  (`requireProvenWallet`), never an address from the browser.
- **Recorded only from the validated ledger.** A mint, a sale listing and a purchase are each written
  only after `getValidatedTx(hash)` returns a validated `tesSUCCESS` transaction of the right type,
  signed by the expected wallet. A mint must also carry the collectible taxon and the edition's URI; a
  purchase must have moved this edition's NFT through this edition's offer.
- **Exactly once.** Each write is one update conditional on the token still waiting for that wallet
  request, so repeated or concurrent reconciles change nothing.
- **Declined, expired or failed** requests free the edition: a failed mint is retried on the same
  edition, a failed purchase leaves the edition for sale if its offer is still on the ledger.
- **Stale offers.** Before the buyer's wallet is asked, the sell offer is read from the ledger
  (`getOffers`: same index, owner, price, no destination, not expired) and the seller must still hold
  the NFT (`verifyOwner`). If not, the token is marked `STALE` and the buyer is told the offer was taken
  or withdrawn and nothing was charged (409). The buyer must also be able to pay (`getWalletReadiness`).
  One purchase is in flight per edition.
- **Ownership.** `/collectibles` starts from the tokens the app recorded for the wallet (validated
  mints and purchases) and checks each with `verifyOwner`. A token the wallet no longer holds is not
  shown and is dropped from the wallet's record.

## Routes

| Route | Who | What |
|---|---|---|
| `POST /api/assets` | seller | multipart `file` + `rightsConfirmed=true`. 201 `MediaAssetView`. 400 `RIGHTS_NOT_CONFIRMED` / `NO_FILE`, 415 `UNSUPPORTED_MEDIA_TYPE`, 413 `FILE_TOO_LARGE`, 503 `MEDIA_STORAGE_FAILED` |
| `GET /api/assets/:id/content` | public if published, else uploader | The media bytes |
| `POST /api/collectibles` | seller | Create a draft |
| `GET /api/collectibles` | seller | Own collectibles, drafts included |
| `GET /api/collectibles/:id` | public if published, else seller | Listing with editions |
| `PATCH /api/collectibles/:id` | seller | Edit a draft; `{ "status": "PUBLISHED" }` publishes. After that only `priceDrops` may change |
| `GET /api/collectibles/tokens/:id/metadata` | public | Raw metadata JSON |
| `POST /api/collectibles/:id/mint-intent` | seller + wallet | Next edition's `NFTokenMint` request |
| `POST /api/collectibles/tokens/:id/sale-intent` | seller + wallet | `NFTokenCreateOffer` request |
| `POST /api/collectibles/tokens/:id/accept-intent` | customer + wallet | `NFTokenAcceptOffer` request, after the stale check |
| `GET /api/collectibles/tokens/:id` | public | One edition, after reconciling what is in flight |
| `GET /api/collectibles/mine` | signed in + wallet | Collectibles the wallet holds, verified on the ledger |
| `GET /api/sellers/:id/collectibles` | public | A seller's published collectibles |

Pages: `/seller/collectibles`, `/collectibles/:id`, `/collectibles`. Mountable server components
(`sections.tsx`): `SellerCollectiblesSection({ sellerId })`, `OwnedCollectiblesSection({ walletAddress })`,
`BrowseCollectiblesSection()`.

## What is and is not verified

- Verified by `src/features/collectibles/collectibles.int.test.ts` against Postgres, with media storage,
  Xaman and the ledger faked: upload validation, access to unpublished media, publishing, the mint
  recorded only from the validated transaction and only once, a foreign NFT refused, a declined mint
  freeing its edition, a purchase recorded from the validated accept with the owner moved to the buyer,
  and a stale offer refused before the wallet is asked.
- Verified by hand against a local dev server: the upload route (multipart, errors), ranged media
  reads, draft privacy, publishing, the metadata URL and the three pages.
- **Verified on live XRPL Testnet** by `tests/testnet/collectibles.testnet.test.ts` (on demand,
  `npm run test:testnet`): one edition is minted, listed for sale and bought by another wallet, each
  recorded only from its validated transaction. The NFT carries the collectible taxon and the edition's
  metadata URI, the buyer's collection shows it after a ledger ownership check, the seller's doesn't,
  and no ticket record is created. The person approving in Xaman is simulated there, as in the ticket
  lifecycle suite.
- **Not yet done with a real phone.** Nobody has approved a collectible mint, listing or purchase in
  the Xaman app itself.

## Limitations and follow-ups

- **Storage.** Local disk only. It needs a persistent disk; a serverless deployment (Vercel) loses
  uploads. An S3-compatible adapter implementing `MediaStorage` is the follow-up (`STORAGE_*` placeholders
  already exist in `.env.example`). Uploads are buffered in memory (50 MB at most).
- **Rights are a declaration**, not a check: nothing verifies the seller actually owns the content.
  There is no takedown or unpublish flow; a published collectible cannot be withdrawn, because NFTs
  already minted point at its metadata.
- **Published media is public** at its URL, with or without owning the NFT. The NFT proves ownership of
  the edition, it does not gate the file.
- Metadata is served by the app and rendered from the (frozen) listing; it is not content-addressed.
- One approval per edition, and per sale listing. No batch mint, no cancel-offer or price change for a
  live listing (the seller can cancel in their wallet; the app then marks it stale and allows relisting).
- An unapproved wallet request holds its edition until it expires (10 minutes) or is declined.
- **A mint approved late is not recorded.** Xaman lets a request that was opened in time be approved
  after it expired. By then the app has freed the edition, so that mint is not recorded, and minting
  the edition again creates a second NFT for it in the seller's wallet. The ticket flow closes this in
  XRPL-027 with a `LastLedgerSequence` deadline on the mint; collectibles should adopt the same.
- The collection lists collectibles the app recorded for the wallet. One received by a transfer made
  outside the app does not appear until a ledger-wide scan is added.
- An uploaded file that is never attached to a collectible stays in storage (no cleanup job).
- No idempotency keys on the intent routes; conditional claims prevent double purchases, and a repeated
  mint click would claim the next edition.
- Royalties (`TransferFee`) are not set.
- Collectible sales are summarised on `/seller/analytics` (XRPL-078, `docs/storefront-analytics.md`).
